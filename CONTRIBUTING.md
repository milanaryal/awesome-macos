# Contributing

Thank you for helping keep this list useful and accurate.

## Before proposing an entry

- Confirm that the app or resource works on a currently supported macOS release.
- Link to the canonical project, vendor, App Store, or source repository page.
- Search the README and open pull requests to avoid duplicates.
- Use a concise, factual description. Avoid advertising language and unsupported claims.
- Add only labels that you can verify: open source, freeware, App Store, or Homebrew.
- Disclose in the pull request if you own, maintain, work for, or are paid by the project.

## Formatting

Place the entry in the most specific existing section and preserve alphabetical
order. Use this format:

```markdown
- [Project](https://example.com/) - One factual sentence describing the project.
```

Optional badges may follow the description when their links are accurate.

## Pull requests

Keep each pull request focused. Explain why the entry belongs in the list and
how its URL, availability, and labels were verified. Maintainers may request
changes, move an entry, or decline products that are unmaintained, misleading,
duplicative, unsafe, or outside the list's scope.

Corrections to existing entries are welcome. For a dead link, include the new
canonical destination or evidence that the project is no longer available.
